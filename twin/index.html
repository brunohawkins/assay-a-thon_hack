A single-cell assay, run on a line of small chips

Describe the protocol, and get the chips to run it on, an operator that runs it safely, and a digital twin that shows every step at real scale.

Present

    The problem

    A single-cell assay is a long chain of liquid handling. Cells are grown, lifted off, wrapped in capsules, lysed, reverse-transcribed, split, amplified and cleaned up. At the bench nearly every one of those steps is a manual transfer from tube to tube, and each one costs skilled time and adds variation.

    Microfluidic chips could run the chain, but each chip is drawn by hand for one protocol, and a chip left running needs someone watching that the liquid goes where it should.

    Our approach

    Treat the protocol and the chip as files that every tool reads. Cells travel in hydrogel capsules that stay put on mesh floors while liquids are swapped around them, so one chip can take the cells through several steps without losing them.

    • Design. A written protocol becomes a chip, assembled from library parts that are known to fabricate.
    • Run. An AI operator proposes each action. The chip's own flow model simulates it, and fixed safety rules approve or refuse it before anything moves.
    • See. The digital twin draws every chip from the same files, at real scale, and plays each run step by step.

    What we built this weekend, and why

    Shared file formats
    For protocols, chips, runs and the pipeline. Six people could build in parallel against placeholders, and every tool reads the same files.
    Six chips, culture to clean-up
    Each 30 × 20 mm and 0.3 mm deep, one fluidic layer: the envelope both resin printing and hot embossing can make.
    Prompt to chip
    A typed description becomes a chip spec built from Flowmatter library parts, and our checker tests it against the fabrication rules.
    CAD for every part
    STL files named by chamber, so the printer and the twin use the same geometry.
    The operator and its closed loop
    It plans, checks and corrects a run. With no hardware this weekend, it runs against a virtual chip with injected faults such as a clog.
    This digital twin
    One picture of the whole line for the team and for this demo: every chip, the sample moving through, and a bench view that runs beside the real chip.
    Module 1, made for a food-dye run
    To test the flow model on a real chip: if the dye arrives when the twin says it will, the model has earned some trust.

    What is new

    • Routing by flow, not valves. Module 1 grows neurons, glia and astrocytes in three chambers that meet at one junction. Which ports are fed, open or plugged decides whether the cultures stay apart or share medium.
    • The AI does not get the last word. The operator suggests, the flow model predicts, and deterministic rules decide. Asked to do something that would mix the cultures, it refuses and says why.
    • One description drives every tool. The protocol and the chip spec feed the CAD, the operator and the twin, so the picture cannot drift away from the design.
    • Designs made of parts that print. Generated chips are assembled from blocks that fit the 30 × 20 mm, 0.3 mm deep envelope, and every design is checked against it.
    • The model and the bench on one clock. The twin predicts when the dye reaches each chamber; the bench demo records when it actually does.

    Where it stands

    • Everything on screen is a simulation. There are no pumps, cameras or wet-lab data this weekend, and the closed loop runs on a virtual chip.
    • All six chips have a spec and a protocol. Module 1 is being made for the food-dye run; the others exist in the twin.
    • Split-and-pool barcoding is a placeholder for now, so the current line gives data per lane, not per cell. Whether to add it back is an open question.
    • Capsule retention cannot be printed at this size: it needs a bought mesh insert or sedimentation.
